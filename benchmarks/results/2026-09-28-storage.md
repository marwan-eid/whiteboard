# Storage per edit with full history

This measures [docs/BENCHMARKS.md](../../docs/BENCHMARKS.md) target 4. Storage size depends on the data and on Postgres, not on the machine, so the local run is representative. It still ran on a laptop, not on the benchmark rig.

## Setup

| | |
|---|---|
| Code | commit `87ac8ae` plus [cmd/storagebench](../../cmd/storagebench/main.go) (added in the commit that adds this file) |
| Database | Postgres 17 (`postgres:17-alpine` from `compose.yaml`), in a scratch database `storagebench` |
| Machine | Intel i7-8750H laptop, Docker Desktop on Windows 11 |
| Command | `go run ./cmd/storagebench -db postgres://whiteboard:whiteboard@localhost:5432/storagebench?sslmode=disable -edits N`, for N = 10k, 100k and 1M |

**Edit stream:** one op per batch, from 20 editors, appended 50 batches at a time (like board ticks). The mix matches the load-test scenario:

| Share | Edit |
|---|---|
| 20% | create a shape, with all its style properties |
| 60% | move (x, y) |
| 15% | text edit |
| 5% | delete |

**Measured:**
- **On disk:** `pg_total_relation_size`, which covers the table, its indexes and TOAST: what storage actually costs.
- **Payload:** the encoded bytes alone.

The "compacted" rows are taken after one snapshot at the end, `Compact` up to it, and `VACUUM FULL`. Without the vacuum, the space of deleted rows is only reclaimed later.

## Results

| Edits | Log only, on disk | After snapshot + compaction, on disk | of which segments | of which snapshot | Reduction |
|---|---|---|---|---|---|
| 10,000 | 181.0 B/edit | 42.6 B/edit | 29.5 | 11.5 | 4.2× |
| 100,000 | 172.8 B/edit | 31.9 B/edit | 24.2 | 7.5 | 5.4× |
| 1,000,000 | 172.0 B/edit | **31.3 B/edit** | 24.0 | 7.2 | **5.5×** |

At 1M edits:
- **Full history in 31 MB:** the compacted log is 24 MB, plus a 7 MB snapshot of the 150,203 live objects.
- **Raw log would be 172 MB:** of that, the encoded payload is only about 50 bytes per edit (49.6 MB). The rest is Postgres per-row overhead (tuple header, primary-key index) for one row per edit, which is what compaction removes.
- **Segments:** zstd-compressed runs of 10,000 entries, with a payload of 23 bytes per edit.

**Not included:**
- **Snapshot retention:** every snapshot is kept. A board that snapshots every 5,000 edits accumulates them, and ADR-0004's retention thinning is not implemented yet.
- **Backups.**
